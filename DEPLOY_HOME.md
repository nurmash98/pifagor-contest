# Перенос Pifagor Contest на свой Ubuntu-сервер

Заменяет Render + Neon. Старые инструкции (`DEPLOY.md` — Oracle, `DEPLOY_RENDER.md`) устарели.

> Скрипты написаны и проверены на синтаксис, но запускаются впервые именно у вас. Делайте шаги по порядку,
> а переключение учеников — только после «репетиции» (шаг 5).

## 0. Что нужно знать заранее
- Ubuntu лучше **на самом компьютере** (или в виртуалке с «мостовой» сетью). В WSL на Windows сервер для интернета работать будет плохо (нет автозапуска, свой внутренний IP).
- Сайт: nginx → gunicorn → PostgreSQL, всё на одном компьютере. Код учеников запускается под отдельным пользователем `pifagorbox`, у которого нет ни доступа к файлам сайта, ни сети.
- Для работы из интернета нужны: белый IP, домен (или поддомен), проброс портов **80 и 443** на роутере. Порт 22 (SSH) наружу **не открывать**.

## 1. Установка (в домашней сети, белый IP пока не нужен)
```bash
sudo apt-get update && sudo apt-get install -y git
git clone -b feature/tags-and-courses https://github.com/nurmash98/pifagor-contest.git ~/pifagor-src
cd ~/pifagor-src/deploy
# Версию PostgreSQL узнайте в Neon (Dashboard → Settings → PostgreSQL version) и укажите её:
PG_MAJOR=17 DOMAIN=ваш.домен.kz bash deploy.sh
```
`DOMAIN` можно не указывать — добавите позже в `/etc/pifagor/pifagor.env` (`DJANGO_ALLOWED_HOSTS`) и в `/etc/nginx/sites-available/pifagor`.
Чтобы ученики **не вышли из аккаунтов** после переезда, возьмите `DJANGO_SECRET_KEY` со страницы Environment в Render и передайте: `DJANGO_SECRET_KEY='...' bash deploy.sh`.

После установки сайт открывается по адресу `http://IP-сервера/` из домашней сети. Скрипт в конце проверяет изоляцию кода учеников (`sandbox_check`) — все пункты должны быть «OK».

Переменные Render (`DJANGO_REGISTRATION_OPEN`, `HOLIDAY_FORCE` и др.) допишите в `/etc/pifagor/pifagor.env`, затем `sudo systemctl restart pifagor`.

## 2. Полезные команды
| Что | Команда |
|---|---|
| Создать администратора | `sudo pifagor-manage createsuperuser` |
| Любая команда manage.py | `sudo pifagor-manage <команда>` |
| Обновить сайт из GitHub | `sudo pifagor-update` |
| Автообновление (как в Render) | `sudo systemctl enable --now pifagor-update.timer` |
| Копия базы сейчас | `sudo pifagor-backup` (каждую ночь в 03:30 — автоматически, хранится 14 дней) |
| Логи сайта | `sudo journalctl -u pifagor -n 100` |
| Перезапуск | `sudo systemctl restart pifagor` |

## 3. Версия PostgreSQL
Локальная версия должна быть **не ниже** версии в Neon, иначе восстановление не пройдёт. Если сервер уже установлен не с той версией (база пока пустая) — запустите `PG_MAJOR=нужная bash deploy.sh` ещё раз.

## 4. Перенос базы из Neon
Строку подключения возьмите в Neon (Connect → Connection string, с паролем). **Вводите её только на сервере** и никому не отправляйте.
```bash
cd ~/pifagor-src/deploy
sudo apt-get install -y postgresql-client   # если pg_dump ещё нет
NEON_URL='postgresql://...?sslmode=require' bash migrate_from_neon.sh
```
Скрипт: сверяет версии → останавливает сайт → делает копию Neon (сохраняется в `/var/backups/pifagor/neon-*.dump`) → заменяет локальную базу → сверяет число строк в каждой таблице → запускает сайт. Его можно запускать повторно: каждый раз локальная база заменяется свежей копией.

## 5. Репетиция и боевой переход
1. Репетиция: выполните шаг 4, зайдите на сайт из домашней сети, проверьте вход учителя, задачи, рейтинг, подарок.
2. В день переезда (лучше вечером, когда нет уроков): в Render нажмите **Suspend**, чтобы ученики не писали в старую базу → снова `migrate_from_neon.sh` → проверка.
3. Направьте домен на новый сервер (шаг 6). Если домен остаётся прежним — DNS обновится за минуты-часы.
4. Neon и Render **не удаляйте минимум неделю** — это запасной вариант. Потом можно удалить.

## 6. Белый IP, домен, HTTPS
1. У провайдера (Казахтелеком) закажите услугу «статический белый IP». Проверка: IP в настройках роутера должен совпадать с тем, что показывает сайт 2ip.ru.
2. В роутере: закрепите за сервером постоянный адрес (static DHCP / резервирование по MAC) и пробросьте **только TCP 80 и 443** на этот адрес.
3. В панели домена (ps.kz) создайте A-запись: `ваш.домен.kz` → белый IP.
4. Когда домен открывает сайт по http, получите сертификат:
```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d ваш.домен.kz
```
Продление автоматическое. Не забудьте домен в `DJANGO_ALLOWED_HOSTS`.

### Пока белого IP нет
- **Cloudflare Tunnel** — сайт доступен из интернета без проброса портов (нужен бесплатный аккаунт Cloudflare и перенос DNS домена на Cloudflare). Туннель направляйте на `http://localhost:80`.
- **Tailscale** — доступ только для вас/учителей (не для учеников), удобно для администрирования.

## 7. Надёжность дома
- Нужен **ИБП** (хотя бы небольшой): внезапное отключение света может повредить базу.
- В BIOS включите «Restore on AC Power Loss → Power On», чтобы сервер сам включался после отключения света.
- Копии базы лежат на том же компьютере. Настройте копирование на другой компьютер/диск: добавьте в `/etc/systemd/system/pifagor-backup.service` строку `Environment=BACKUP_RSYNC_TARGET=user@другой-пк:/backups/pifagor/` (нужен SSH-ключ).
- Обновления безопасности: `sudo apt-get install -y unattended-upgrades`.

## 8. Безопасность (как защищён код учеников)
Присланный ученическим кодом Python запускается так: `sudo` → пользователь `pifagorbox` → `prlimit` (CPU/память/процессы) → `timeout` → `python -I`. Он **не видит** файлы сайта (каталог 750), переменные окружения и файл `/etc/pifagor/pifagor.env`, а iptables запрещает ему любую сеть (в том числе доступ к базе на localhost). Проверка: `sudo pifagor-manage sandbox_check --env-file /etc/pifagor/pifagor.env`. Если проверка не проходит — **не открывайте сайт наружу**, пришлите вывод.
Брандмауэр: открыты только 80/443; SSH — только из домашней сети.
